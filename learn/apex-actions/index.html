How an agent picks a tool

An agent doesn't read your Apex code. It reads the labels and descriptions you attach to it, and decides from those alone whether your action fits what the user asked.

The user asks

"Where's my order A-1042?"

The agent reads descriptions

"Returns the current status of an order, given its order number." That matches.

Your Apex runs

The agent passes in the order number, and your code returns the status.

Wire it into Agent Script

In the agent, the action points at your class with an apex:// target. The inputs and outputs line up with your Apex variables.

  • target: "apex://OrderLookupService" names the class. Each class has one invocable method, so that's all the agent needs.
  • orderNumber and status use the same names as the @InvocableVariable fields, as Salesforce's own recipes do.
  • The descriptions here can be more specific than the ones in Apex. Use them to explain how this particular agent should use the action.

Description makeover

Descriptions are the part most people rush, and the part the AI depends on. Pick the better one each time.
